The story

Why I built it.

I run several machines — a desktop, a couple of laptops, a home server. I wanted one assistant that could actually operate them: not just answer questions, but open apps, move files, run commands, take a screenshot, reboot a box — from my phone, from anywhere.

OpenClaw showed me the shape of that future: a personal AI wired into your digital life. But the usual way to reach one — a Telegram or WhatsApp bot, or a hosted service — sat wrong with me, for two reasons.

Privacy. Every message, file, and command would pass through someone else's servers. My machines, my data — routed through a third party I had to trust.
Dependency. The day their service had downtime, or my bot account got flagged, my assistant would simply vanish. I didn't want a controller I didn't control.

So I built VClaw to flip it. The agent runs on my hardware — no chat-platform middleman, no provider to depend on. If my machine is on, my assistant is up. And I can still reach it from outside my network, privately, over my own Cloudflare WARP mesh — with nothing exposed to the public internet.

What began as "control my own machines" grew into a full control plane: a multi-agent core, an admin console, interactive chat, a skills studio, Teams-grade remote desktop, native apps — all local-first, all with me as the kill switch. Here's what came out of it.

What I built

A control plane, end to end.

Fleet · one console

Every machine, one command deck.

Pair each computer once with a QR code — then it's a node in the fleet: named, permissioned, live, reachable anywhere. I built per-device capability grants with an Approve/Deny tap for anything risky.

  • QR pairing → per-device permissions, revocable instantly
  • Live CPU / memory / disk, processes, uptime
  • Capability allowlist + human-in-the-loop approval

How I built it

The engineering, and the calls I made.

A Python core with a clean contracts layer, a self-contained web console, native clients, and a C++ extension for the low-level stuff. A few decisions I'm proud of:

WebRTC over VNC

Wanted Teams-grade quality, so I tunneled WebRTC through VClaw's own auth — no GPL server, no extra exposed port.

AG-UI-style HIL

An event protocol so the agent renders real components (multi-select, forms) and gets structured answers back.

Capability + approval

Every risky action is capability-gated and waits for a tap. Secrets never enter the model or child processes.

WARP, not a public bot

Remote access over a private Cloudflare mesh — reachable anywhere, nothing exposed to the internet.

Multi-agent core

LangGraph supervisor → specialist workers, multi-provider (Claude/OpenAI/Kimi/Ollama), vector memory + reflection.

One-line install

Installs, runs in the background, auto-starts at login, survives reboots — managed like a service.
